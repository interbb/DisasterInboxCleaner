# 문자함 정리 (DisasterInboxCleaner)

삼성 메시지를 기본 문자 앱으로 둔 채, 삼성 메시지함에서 두 종류의 문자를 자동으로 지우는 안드로이드 앱입니다.

- 한국형 Android Cell Broadcast가 메시지함에 만드는 `#CMAS#` 재난문자 복사본
- 본문이 `(광고)` 또는 `[광고]`로 시작하거나, `[Web발신]`처럼 통신사 표시 뒤에 그 표기가 오는 광고 문자 (정보통신망법 의무 표기)

> **동작 확인 기기**: Galaxy Z Fold8 (SM-F971N, Android 17 / One UI 9, 기본 문자 앱 삼성 메시지).
> 문자함 동작과 알림 처리는 제조사와 One UI 버전에 따라 다르므로 다른 기기에서는 결과가 다를 수
> 있습니다. 안내 화면에 들어가는 설정 화면 사진도 이 기기 기준입니다.

## 보존되는 항목

- 재난문자 수신 알림, 팝업, 경고음
- `설정 > 안전 및 긴급`의 Cell Broadcast 원본 기록
- 일반 SMS/MMS와 기존 메시지

## 프라이버시

- 재난문자 경로는 발신 주소(`#CMAS#`)만 보고 본문을 조회하거나 저장하지 않습니다.
- 광고 문자 경로는 판정을 위해 본문 앞부분을 읽고, 삭제 이력에 시각·발신번호·본문 앞 30자만 앱 내부 파일(`files/ad_cleanup_history.tsv`)에 남깁니다. 최근 300건, 30일까지 보관하며 전체 본문은 어디에도 저장하지 않습니다.
- 인터넷 권한은 동봉 adb가 127.0.0.1(기기 자신)로만 쓰며 외부로 통신하지 않습니다.
- 기존 문자 정리 화면은 사용자가 항목을 고를 수 있도록 본문을 기기 메모리에만 잠시 표시하고, 화면을 나가면 목록을 비웁니다.

## 빌드

JDK 17과 Android SDK가 필요합니다. Android Studio로 열거나, SDK 위치를 `local.properties`에 적고 명령줄에서 빌드하면 됩니다.

```bash
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties   # macOS 기준
./gradlew testDebugUnitTest assembleDebug
```

결과물은 `app/build/outputs/apk/debug/app-debug.apk`입니다. `compileSdk 37`, `minSdk 30`, `targetSdk 35`이고 arm64 기기만 지원합니다(동봉 adb 바이너리가 arm64 전용).

## 내려받기

[Releases](https://github.com/interbb/DisasterInboxCleaner/releases)에서 APK를 받을 수 있습니다. Google Play에 올린 앱이 아니므로, 아래 **설치** 절차를 그대로 따라 주세요.

APK는 디버그 키로 서명돼 있습니다. 직접 빌드하면 서명 키가 달라져 덮어쓰기가 안 되니, 그때는 기존 앱을 지우고 새로 설치해야 합니다.

## 설치

폰에서 APK 파일로 설치하는 경우와 PC에서 adb로 설치하는 경우가 있습니다. **폰만으로 설치하실 거면 아래 세 관문을 차례로 넘으시면 됩니다.**

### 1. 출처를 알 수 없는 앱 허용

APK를 열면 "이 출처의 앱은 설치할 수 없습니다" 같은 안내가 뜹니다. 이때 나오는 `설정` 버튼을 누르면 바로 해당 화면으로 갑니다. 직접 찾아가려면 **설정 → 앱 → 특수 접근 → 알 수 없는 앱 설치**에서, APK를 연 앱(크롬, 내 파일 등)을 골라 **이 출처 허용**을 켜면 됩니다.

이 권한은 앱 단위입니다. 크롬으로 받아 크롬에서 열었다면 크롬에 허용해야 하고, 파일 관리자에서 열었다면 그쪽에 허용해야 합니다. 설치가 끝난 뒤에는 다시 꺼 두셔도 됩니다.

### 2. Play 프로텍트 경고

설치 직전에 "알 수 없는 앱입니다" 또는 "Play 프로텍트가 앱을 스캔했습니다" 같은 경고가 뜹니다. Play 스토어를 거치지 않은 앱이면 서명 여부와 무관하게 나오는 안내입니다.

**이 한 번만 넘기는 방법**을 권합니다. 경고창에서 `자세히` 또는 `더보기`를 누르면 **무시하고 설치**가 나옵니다. 이것을 누르면 이 설치만 진행되고 보호 기능은 그대로 유지됩니다.

그래도 막히면 Play 프로텍트를 잠시 끌 수 있습니다. **Play 스토어 → 오른쪽 위 프로필 → Play 프로텍트 → 오른쪽 위 설정(톱니) → 기기 보안 위협 스캔**을 끄고 설치한 뒤, **설치가 끝나면 다시 켜 주세요.** 이 스위치는 이 앱 하나가 아니라 앞으로 설치하는 모든 앱의 검사를 멈춥니다. 꺼 둔 채로 두면 다른 경로로 받은 악성 앱도 걸러지지 않으니, 끄는 시간은 설치하는 동안으로 한정하시는 편이 안전합니다.

### 3. 제한된 설정 허용 (이게 진짜 관문입니다)

이 앱은 문자 읽기 권한을 씁니다. Android는 스토어를 거치지 않고 설치된 앱에 대해 이런 민감한 권한을 기본으로 막아 두고, 앱 안에서 권한을 요청해도 **아무 반응 없이 무시되는 것처럼 보입니다.**

풀어 주는 곳은 여기입니다. **설정 → 애플리케이션 → 문자함 정리 → 오른쪽 위 점 세 개 → 제한된 설정 허용.** 이 항목은 앱을 설치한 직후에만 보이는 경우가 있으니, 안 보이면 앱을 한 번 실행한 뒤 다시 들어가 보세요.

이 절차를 건너뛰면 튜토리얼의 문자 읽기 단계에서 허용을 눌러도 진행되지 않습니다.

### PC에서 설치하는 경우

adb로 설치하면 위 1·3번 관문이 없습니다.

```bash
adb install -r app-debug.apk
```

직접 빌드한 경우 경로는 `app/build/outputs/apk/debug/app-debug.apk`입니다.

## 최초 설정

처음 설정 화면이 네 가지를 안내합니다.

1. **알림 접근**: `시스템 알림 접근 화면 열기` → **문자함 감시** 허용. 허용할 때 저장되는 "허용 알림 유형"(대화·알림·무음)은 최초 허용 시점에 고정되므로, 알림을 감지하지 못하면 앱을 지우고 다시 설치한 뒤 새로 허용해야 합니다.
2. **문자 읽기**: `문자 권한 요청` 버튼으로 앱 안에서 요청합니다.
3. **메시지함 삭제 권한(WRITE_SMS 앱옵)**: Android에는 이 권한을 켜는 설정 화면이 없어 셸 권한이 필요합니다. 두 가지 방법이 있습니다.
   - **폰에서 받기(권장, PC 불필요)**: 튜토리얼이 안내하는 대로 개발자 옵션과 무선 디버깅을 켜고 `권한 부여 시작`을 누른 뒤, `페어링 코드로 기기 페어링` 창을 **열어 둔 채** 알림창을 내려 **6자리 코드만** 입력하면 됩니다. 앱이 동봉한 adb로 폰 자신과 페어링·연결해 `appops set … WRITE_SMS allow`를 실행하고 결과를 검증합니다. 포트는 앱이 mDNS로 직접 찾습니다. 못 찾은 경우에만 알림이 포트를 함께 요청하며, 그때는 페어링 창의 `IP 주소 및 포트`에서 콜론 뒤 숫자를 코드 앞에 붙여 넣습니다(예: `43419 123456`). 한 번 받으면 재부팅과 업데이트에도 유지되고, 끝나면 무선 디버깅을 꺼도 됩니다.
   - **PC에서 adb(대안)**: `adb shell appops set com.interbb.disasterinboxcleaner WRITE_SMS allow`. 카드의 `다른 방법`에서 명령을 복사할 수 있습니다.
4. **배터리 최적화 제외(필수)**: `배터리 최적화 제외 요청`을 승인하고, 삼성 기기는 설정 > 배터리 > 백그라운드 사용 제한 > 절전 예외 앱에도 추가합니다. 백그라운드에서 앱이 얼면 문자함 변경과 알림을 늦게 받아 정리가 미뤄지므로, 이 항목이 없으면 설정을 완료할 수 없습니다(모니터링 자체는 이 항목 없이도 동작하지만 느려집니다).

권한을 되돌리려면:

```bash
adb shell appops set com.interbb.disasterinboxcleaner WRITE_SMS default
adb shell pm revoke com.interbb.disasterinboxcleaner android.permission.READ_SMS
```

### 동봉 adb와 페어링 키

- `app/src/main/jniLibs/arm64-v8a/libadb.so`는 AOSP adb의 Android arm64 빌드(Apache License 2.0)로, LADB 저장소에서 가져왔습니다(`app/src/main/assets/licenses/`). arm64 기기 전용이며 앱은 이 바이너리를 폰 안(127.0.0.1)에서만 씁니다. 서버 포트는 5038입니다.
- 페어링 키는 앱 내부 `files/adbhome/.android/`에만 있습니다. 설정 > 개발자 옵션 > 무선 디버깅 > 페어링된 기기 목록에서 이 앱 항목을 지우면 다시는 접속할 수 없습니다.
- 페어링 코드와 포트는 로그·파일에 남기지 않습니다.
- adb 로그는 앱 전용 캐시(`cacheDir/adbtmp`)에만 남고, 코드는 기록되지 않습니다.

## 백그라운드 동작

사용자가 알림 접근을 허용하면 Android가 `NotificationListenerService`를 관리합니다. 앱은 재난문자 알림·삼성 메시지 알림과 SMS 저장소 변경을 감지하고 수신 직후 여러 차례 제한적으로 정리를 시도합니다. 재부팅 후에도 기능이 켜져 있으면 서비스 재연결을 요청합니다. 권한 부여 진행 중에만 잠깐 포그라운드 서비스와 코드 입력 알림을 띄우고, 끝나면 사라집니다.

광고 문자를 지운 뒤에는 본문이 `(광고)`/`[광고]`로 시작하거나 통신사 표시 뒤에 그 표기가 오는 삼성 메시지 알림을 닫습니다. 재난문자 알림은 닫지 않습니다.

## 기존 문자 정리

홈의 `기존 재난문자 선택 정리`와 `기존 광고 문자 정리`에서 이미 쌓인 문자를 지웁니다. 실제 삭제 전 확인창이 표시됩니다.

- 삭제 요청은 `content://sms` 경로로 보냅니다. `content://sms/inbox` 경로는 Android 저장소가 삭제를 거부하고, `content://sms/N` 경로는 where절을 무시하기 때문입니다.
- Android는 기본 문자 앱이 아닌 앱에 제한된 조회 목록을 제공하고, 이 기기는 그 위에 재난문자 행을 숨깁니다. 그래서 재난문자는 목록 없이 전체 삭제만 되고, 광고 문자는 목록에서 골라 지울 수 있습니다.

## 한계

- 수신음·진동과 화면 위에 잠깐 뜨는 배너는 이 앱이 막을 수 없습니다. 알림 리스너는 알림이 **게시된 뒤에만** 호출되는데 배너는 그 게시와 함께 그려지고, 게시 전에 끼어들 수 있는 `NotificationAssistantService`는 스토어를 거치지 않고 설치한 앱에 부여되지 않습니다(`cmd notification allow_assistant`는 조용히 실패하면서 기본 도우미 재적용만 막을 수 있으니 실행하지 마세요).
  - 배너까지 없애려면 삼성 메시지 자체 기능을 쓰세요. 메시지 → 더보기 → 설정 → `스팸 및 차단 번호 관리` → `차단 문구`에 `(광고)`와 `[광고]`를 **'포함'** 조건으로 등록하면 알림이 만들어지기 전에 걸러집니다. `단어 일치`를 고르면 앞뒤 공백을 요구해 `(광고)[KT]…`처럼 붙어 오는 실제 광고를 놓칩니다. 대신 본문 중간에 그 표기가 든 정상 문자도 차단되고, 차단된 문자는 이 앱의 삭제 이력에 남지 않습니다.
  - 배너만 끄려면 설정 → 알림 → 메시지 → `팝업으로 표시`를 꺼도 됩니다. 모든 문자에 적용되고 소리·알림창은 남으며, 재난문자는 다른 패키지라 영향이 없습니다.
- `(광고)`/`[광고]` 표기 없는 스팸, MMS·RCS 광고, 삼성 스팸함으로 이미 이동한 문자는 대상이 아닙니다.
- 알림 패키지는 삼성 메시지 하나입니다. 기본 문자 앱이 바뀌면 상수 한 곳(`DisasterNotificationListenerService.SAMSUNG_MESSAGES_PACKAGE`)을 바꿔야 합니다.
- 폰에서 권한 부여는 Android 11 이상, arm64, Wi-Fi 연결이 필요하고, 개발자 옵션·무선 디버깅·페어링 창 열기와 코드 입력은 사용자가 직접 합니다. 안내 이미지는 Galaxy Fold8(One UI 9, 접은 화면) 기준입니다.
